### Backtest performance work (~29x faster)
Profiling showed two hotspots, not the strategy logic:

1. **`pivot_to_snapshots` (src/atr/data/base.py)** — used `groupby("ts")` + `itertuples`
   per group: one group object per bar. 40.8s of a 69s run. Rewritten on numpy arrays,
   single pass over sorted timestamps; groups found via `np.unique(..., return_index=True)`.
   Affects every feed (csv, synthetic, iifl).
2. **`ctx.row()` (src/atr/strategy/base.py)** — returned `frame.iloc[i]` (a Series); each
   scalar access cost ~90us through pandas indexing. Now returns a tuple built from the
   frame's numpy columns via a cached per-column-set row class. Supports `row.close`,
   `row["close"]`, `row.get("close")`. Cache is keyed on `len(frame)` so live mode
   (where frames grow per tick) invalidates correctly.
3. **`sma_crossover`** — called `ctx.history(symbol, 2)` every bar; now uses
   `shift(1)` columns computed in `prepare()`.

Measured (2 symbols, 1-min bars, Jan–Mar 2024, 17,550 bars):
- load: 20.74s -> 0.25s · engine: 33.73s -> 1.61s · total: 54.47s -> 1.86s
- pytest: sma test 90.67s -> 5.08s; e2e test 20.27s -> 0.71s (suite ~111s -> ~6s)

**Correctness verified**: equity curve and all 1337 fills bit-identical vs the old
implementation (end equity 860304.571440, 668 trades both ways). `pivot_to_snapshots`
output compared field-by-field against the old version incl. ragged groups,
missing/None volume, empty frame.

### Gotcha for future work
- In live mode `LiveRunner._ensure_frames()` calls `strategy.prepare()` on **empty**
  frames, and `_append_bar` uses `pd.concat` — so indicator columns added by `prepare`
  are present but NaN after warmup. Indicators are effectively not recomputed live.
  Pre-existing issue, not introduced by today's changes. Worth fixing before going live.
- `_RowOps` must subclass `tuple`, otherwise it lands after `tuple` in the MRO and
  `tuple.__getitem__` shadows the string-key override.
