# 2026-09-13 — Paper strategies: fabricated win rates replaced with measurements

## What was wrong

`src/atr/research/papers.py` attached a hardcoded `win_rate` to each of its
7 academic models (0.58, 0.64, 0.60, 0.62, 0.59, 0.65, 0.54) and derived
`expected_value` and `confidence_score` from them, with confidence as literals
(0.85–0.94). The UI presented these as `historical_win_rate`. They were
citations dressed up as measurements — the exact thing the project's
"fact based, not emotional" principle forbids.

## What was done

1. **`scripts/fetch_long_history.py`** (new) — pulls real daily history from
   IIFL into `data/iifl_daily/NSEEQ/`. Fetched **18 large caps × 1,631 bars =
   29,358 symbol-bars, 2020-02-17 → 2026-09-11** (6.5 years). The old cache
   held 249 days, which cannot be carved into folds that also leave warmup.

2. **`scripts/validate_paper_strategies.py`** (new) — walk-forward harness over
   the paper strategies with a **random-selection control** (same universe,
   cadence, sizing; random symbols, 8 seeds).

3. **`src/atr/research/papers.py`** — added a `MEASURED` table with a dated
   snapshot, plus `_stats()` / `_confidence()` helpers. Every hardcoded
   constant is gone.

4. **`src/atr/api/main.py`** — `GET /validation` serves the harness output.

5. **`web/src/ValidationPanel.tsx`** (new) — renders claimed vs measured,
   control baseline, and per-check detail. Wired into ResearchPanel as a
   "Measured results" tab.

## The result — none of the 7 passes

Control (8 runs): **mean Sharpe −0.35** (−1.4% to −38.8% return). Random
selection loses money; that is the floor a signal must clear.

Buy & hold on the same window: **Sharpe +0.69, return +49.31%**. Every claimed
win rate was over-optimistic by 3–12 points. Best model (avellaneda_lee, +0.46)
still loses to buy-and-hold, though it clears the control at +3.15σ — the only
one that plausibly contains signal.

## Bugs found and fixed

- **`Row` does not support `in`.** `paper_alpha.py` guarded with
  `"close" in row`. `Row` subclasses tuple and only overrides `get` /
  `__getitem__`, so `in` hits `tuple.__contains__` and tests *values*, not field
  names — always False. Every paper signal was silently skipped, producing a
  clean-looking "0 trades, no edge" that was really "no data". Fixed to
  `row.get("close")`. **This is the trap: it fails as a plausible result.**
- **Batch evaluator in a per-bar loop.** `run_paper_strategy_evaluator` ran all
  7 models per symbol per bar while each adapter kept one. Added
  `EVALUATORS` / `evaluate_one` and switched the adapter. Walk-forward went from
  >8 min for 5 strategies to ~12 min for 7 + 8 control runs.
- **Sparse snapshot grid silently degrades `history()`.** Feeding one symbol per
  snapshot means `BacktestEngine._build_frames` NaN-pads 99% of each symbol's
  frame, so models see no prices. The feed must put **every symbol on every
  bar**. Documented in `build_feed`.

## Verified

98 tests pass. `bun run build` clean. `/validation` returns 18 symbols, 7
results, control mean −0.35.

# 2026-09-13 (later) — 8-section IA restructure shipped

## The structure

Navigation now follows the trader's loop, not the module list. `App.tsx` holds
`GROUPS` in this order, with group labels visible in the sidebar:

| Group | Sections |
|---|---|
| Observe | Dashboard, Markets |
| Decide | Strategies, Signals |
| Act | Trading |
| Learn | Evidence |
| Maintain | Risk, System |

Four of the eight have **deep-linkable sub-tabs**: `markets/{scanner,custom,
charts}`, `signals/{brief,alerts,queue}`, `trading/{portfolio,mode}`,
`evidence/{research,measured,backtest}`.

## Routing — the part that is easy to get wrong

`MarketsTabContainer` used to own its own `useState` for the sub-tab, so
"open this symbol's chart" had nowhere to land: `setTab("charts")` referenced a
tab id that no longer existed and the scanner's chart button silently did
nothing. Sub-tab state was **lifted into `App()`** and the hash became
`#tab/subtab`.

Two compatibility layers, both tested:

- `LEGACY_TABS` maps old ids (`overview`, `scanner`, `charts`, `alerts`,
  `briefing`, `portfolio`, `research`, `backtest`) to their new section.
- `LEGACY_SUB` maps those same ids to the correct *sub-tab*, so `#charts` lands
  on Markets **with Charts open** rather than on the scanner. A redirect that
  lands on the right tab but the wrong panel is still a broken link.

`openChart(symbol)` is the single entry point — it writes `atr.chartSymbol` to
sessionStorage, sets the sub-tab, and navigates. The ticker bar and every
scanner call it.

## Execution mode — paper vs live (new, enforced server-side)

The toggle is one of the six requested features, and it is a **server-side
gate**, not a disabled button:

- `_STATE["execution_mode"]` defaults to `"paper"`.
- `_require_live_execution()` is called by `POST /orders` and
  `POST /trade-signals/{id}/execute`. Read-only endpoints deliberately skip it —
  paper mode must still show the market.
- `POST /risk/execution-mode` rejects `live` without a reason (400).
- `GET /audit` returns an append-only JSONL trail at `data/audit/audit.jsonl`.
  Mode changes, kill-switch actions and orders all land there.

`tests/test_execution_mode.py` — **13 tests**: default-deny, the gate actually
raising, reason required, reason recorded, unknown modes rejected, append-only
(earlier records byte-identical), and survival across a module reload.

## Bug found by those tests

`logger` was **never defined in `main.py`** — three pre-existing `logger.*`
calls would have raised `NameError` the first time they fired. Worse, my new
log call used `{}` placeholders: **`logging` is `%`-style, not
`str.format`**, so `"a {} b {}"` with args raises
`TypeError: not all arguments converted`. Fixed all four call sites to `%s`
and added `logger = logging.getLogger("atr.api")`.
