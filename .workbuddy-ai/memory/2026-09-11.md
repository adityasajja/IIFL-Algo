### 1. BridgePy — FOUND TWO REAL BUGS (both now fixed, commit d5bb69a)

`bridgePy/connector.py` (52KB) is the authoritative connection protocol. It does
**not** decode payloads — it hands raw bytes to callbacks, so our hand-written
186-byte decoder was never "reinventing" anything the SDK does.

What it revealed that we had wrong:
- **MQTT auth was missing entirely.** Official: MQTT 3.1.1 + `clean_session`,
  `username_pw_set(username=<JWT preferred_username>, password="OPENID~~"+token+"~")`,
  `keepalive=20`. Ours: anonymous MQTTv5, keepalive=60. The module docstring
  already claimed auth used the JWT; the code never sent it.
- **`_handle_connect` did `int(rc)`** but paho 2.x passes a `ReasonCode`. It
  compares equal to 0, so connect *looked* fine, then raised inside the callback
  and killed the paho network thread → `is_connected` True while receiving
  nothing. Classic silent failure.

Both verified fixed against the live bridge during market hours.

Note: connector.py also contains an RSA/AES key-exchange path (struct >I lengths
for pubkey/iv/encrypted_aes_key). **Not required** — plain TLS + OPENID password
works. Probably a legacy or alternative auth mode.

### The sync exposed a real bug (worth remembering)
`_pick()` used `row[key] not in (None, "")`. **`nan not in (None, "")` is True**,
so pandas missing values passed through: absent strikes became float NaN and
absent underlyings became the literal string `"NAN"`. And `InstrumentMaster.find()`
rebuilds a row via `DataFrame.to_dict()`, where pandas' `str` dtype stores missing
as NaN — pydantic then rejected the float for the `OptionType` enum, so **every
currency future failed to resolve** with `input_value=nan`.

Fix: added `_missing()` (None / "" / NaN / NaT), applied in `_pick`,
`_parse_expiry` and `find()`. Lesson: `not in (None, "")` is not a null check.
